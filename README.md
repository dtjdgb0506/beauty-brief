# 美妆情报 · 工作流说明

给**品牌市场部高管**看的每日情报：**每天 07:30 汇总前一天**的公开信息，大众护肤 + 医美械字号，3 分钟扫完。
全自动、无人值守、无付费数据账号——只吃公开信息。

> 交付形态：每天 07:30 一封邮件（收件人：`dtjdgb0506@163.com`、`zhangyingzhuo@163.com`，一人一封）+ 网页归档。

---

## 一条命令

```bash
python scripts/run_daily.py --dry-run     # 全流程跑一遍，不发信（先看效果用这个）
python scripts/run_daily.py               # 真发（汇总前一天；当天发过自动跳过）
python scripts/run_daily.py --same-day    # 不推前一天，就推当天
python scripts/run_daily.py --date 2026-11-23 --content-day 2026-11-22   # 指定发送日/内容日
python scripts/run_daily.py --force       # 强制重发
python scripts/run_daily.py --no-collect  # 复用已有候选（调版式时用）
```

内容日规则：默认 = 发送日 − 1 天。打分时"时效"按**内容日**算（昨天发的稿子算最新），
行业媒体发稿有滞后，时间窗会从内容日往前自动放宽到 3~7 天兜底，避免某天只有 3 条。

产物：

| 文件 | 内容 |
|---|---|
| `output/card-<日期>.html` | 邮件正文（也是最终成品） |
| `output/brief-<日期>.json` | 当日结构化简报（含每条 8 个分析字段，站点/二次加工用） |
| `site/<日期>/index.html` | 网页版总览 |
| `site/<日期>/p1..pN.html` | **每件事的独立深度详情页**（时间线/多方视角/风险/建议/问题） |
| `site/index.html` | 往期索引 |
| `logs/<日期>.log` | 全流程日志 |

## 工作流（5 步，全自动）

```

│ collect.py   21 个源，4 种解析器，全部公开网页                        │
│  ├ RSS（国际垂类）      Cosmetics Business / WWD / GCI / C&T / Mintel / 36氪 │
│  ├ HTML 列表（中文垂类） 品观 / 聚美丽 ×3 / 美妆头条 / 青眼                  │
│  ├ HTML 列表（渠道媒体） 赢商网 ×2 / 联商网                                │
│  └ 监管 / 弱信号        中国食品药品网 ×2 / 搜狗微信                        │

├─────────────────────────────────────────────────────────────────┤
│ score.py     去噪 → 分栏 → 打分 → 每栏配额选条                            │
│  · 去噪：泛零售媒体必须"谈美妆"或"渠道商+门店动作"；监管站只收真有事          │

│  · 打分：源权重 × 监测品牌 × 动作强度 × **线下渠道信号** × 时效 × 数字        │

│  · 去重：同事件跨源标题相似度 >0.72 合并，保留分高的                        │
│  · 配额：线下渠道 4 / 竞品动作 4 / 械字号 1 / 趋势 1；弱信号最多 2 条         │
│  · 渠道速览：没进正文的线下动静额外列 3~6 条                                │
│        ↓                                                         │
├─────────────────────────────────────────────────────────────────┤
│ enrich.py    规则抽字段（品牌/价格/渠道/动作）+ 大模型写判断与深度分析           │
│  · 今日 3 件事：headline ≤22 字 + why ≤45 字（单独一次调用）                  │
│  · 每条 8 个分析字段：发生了什么 / 多方视角 / 对各方的意味 / 最该防 /            │

│  · 铁律：只用素材事实、专有名词与原文一致、不编数字、素材不足标 limited         │
│        ↓                                                         │
├─────────────────────────────────────────────────────────────────┤
│ render.py    邮件卡片（table 布局、内联样式、手机可读）+ 网页版 + 往期索引      │
```

## 内容结构（每天）

**栏目顺序：线下渠道优先**（读者最关心渠道），然后竞品动作、械字号与监管、趋势与海外。

**线下渠道（4 条，排第一）**：零售终端、代理商/经销商、门店动作、渠道政策。
每条带一个「渠道动作」标签：开店 / 关店 / 进驻 / 招商 / 加盟 / 代理签约 / 渠道政策 / 价格调整 / 陈列铺货。
正文下面是**渠道速览**：没进正文的线下动静压成一行一条，体现当天线下密度。

**邮件里每条**：标题 + 标签（品牌/渠道动作/价格/渠道/来源）+ **判断**（一句话 so-what）+ 发生了什么 + 最该防 + 建议 + 「看详细分析 →」

**每条的详情页**（点「看详细分析」进）：
1. **发生了什么**：2~3 句，保留数字和时间
2. **多方视角**：品牌方 / 渠道方 / 资本或行业，各自怎么看
3. **对各方的意味**：对品牌、对渠道/代理、对供应链/代工，分别一句
4. **最该防的是什么**：具体踩什么坑、丢什么位置
5. **接下来盯什么**：2~3 条，带时间点或数据口径
6. **可以做什么**：1~2 条本周能执行的动作
7. **值得琢磨的问题**：反常识或悬念
8. 原文链接

**整期结构**：今天必须知道（3 条判断）→ 竞品动作（5）→ 渠道雷达（2）→ 械字号与监管（2）→ 趋势与海外（1）→ 今日小结（一句共同信号）

> 素材只有标题一句话时，详情页会标 `limited`，不会硬编分析。

## 配置（改配置不用改代码）

| 文件 | 管什么 |
|---|---|
| `config/profile.toml` | 监测清单（25 个大众护肤品牌 + 械字号品牌 + 零售商 + 集团）、栏目配额、条数、时间窗、屏蔽词 |
| `config/sources.toml` | 采集源。加一行 `[[source]]` 就多一个源；`type` 决定用哪个解析器 |
| `config/lexicon.toml` | 动作词/渠道词/械字号词/监管词/排除词/栏目强信号 |

改口径的三个常见操作：

- 想多推某类：改 `[quota]` 里对应数字
- 想看某品牌：加进 `[watch].brands`
- 某源太吵：把它的 `tier` 降到 `weak`，或在 `[block]` 加词

## 分工边界（哪些做得做不了）

**能做好**：竞品动作汇总、渠道（零售/代理）雷达、械字号与监管动态、国际新品与集团动作。

**做不了（无付费账号）**：
- 电商上新表现（销量/转化/价格带分布）→ 需魔镜/飞瓜等
- 备案前置信号（新品上市前 1~3 个月）→ NMPA 官网有瑞数 WAF，纯 HTTP 不通
- 抖音/小红书/视频号内容流 → 平台无公开接口，需付费或人工投喂
- 量化趋势（品类增速、份额）→ 需数据服务

详见 `README.md` 的「边界」一节。
